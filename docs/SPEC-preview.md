# Argus 프리뷰 모듈 요구사항 (확정 사항)

## 진행 단계
1. **[완료] 썸네일** — DWM 썸네일 + 투명 오버레이 HUD, 클릭 전환, 편집 모드(이동·비율 고정 크기 조절·자석 붙이기), 위치·크기 저장, 레이아웃 프리셋, "EVE 플레이 중일 때만 표시"
2. **[구현됨, 화면 전환 실측은 일부 미완]** 단축키 — 아래 '단축키' 절 참고
3. **[구현됨]** 전투 로그(`CombatLog` 모듈) + HUD 수치, 태클 리본(상태이상 아이콘 인식) — 아래 '전투 로그'·'상태이상 인식' 절
4. **[구현됨]** 레드박싱 경고 (색조 깜빡임 + 레드박싱 클라이언트 전환 단축키) — 아래 '레드박싱' 절

## 배치 편집·표시 규칙 (1단계 이후 확정)
- '모두 크기' 버튼과 '붙여서 자동 정렬' 버튼은 없앴다.
- 편집 중 **Ctrl 을 누른 채 크기를 조절하면** 활성 프리셋에서 표시 중인 모든 프리뷰가 같은 비율로 함께 조절된다 (각자 왼쪽 위 고정, Ctrl 을 떼면 원래 크기로 복귀). 자석 붙이기는 유지.
- "EVE 플레이 중일 때만 표시" 규칙의 예외: **Argus 자신의 창이 맨 앞이어도 프리뷰가 보인다.**
- 설정 페이지는 기능(모듈)별 그룹 탭으로 나뉜다.

## 후속 UI 결정
- 설정 화면의 입력 규칙: **%로 조절하는 값만 슬라이더 바**(프리뷰 불투명도, HUD 수치 바·태클 리본 투명도 20~100%), 나머지 수치는 **직접 입력 칸 + 오른쪽 위·아래 화살표**(`Argus.Ui.NumberBox`: 정수 1 단위, 소수 항목 0.1 단위, Shift 는 10배, 범위 밖은 끝값으로, 숫자 아닌 입력은 되돌림).
- HUD 겹치는 순서(아래→위): 색조 < 태클 리본 < 이름 라벨·하단 수치 < 전환 키 안내 < 활성 테두리. 리본은 서로 틈 없이 붙고(높이 16, 길이 300 으로 가장자리에서 깔끔히 잘림), 수치는 `3,000` 처럼 쉼표 숫자(k 단위 없음). 레드박싱 전환 키 안내 글자는 16.5(기본보다 50% 큼). 레드박싱 전환 단축키로 그 클라이언트로 옮기면 그 레드박싱 이벤트는 시간이 남아도 종료(새 레드박싱은 다시 살아남).
- 활성 클라이언트의 흰 테두리는 가장 위 층. 하단 수치 바는 5px 위로 올려서 흰 테두리와 겹치지 않게 함 (바 배경은 아래까지 이어짐).
- 배치 편집에서 **Shift + 프리뷰 클릭 = 그 프리뷰를 기본 크기로 재설정** (왼쪽 위 위치 유지).

## 클라이언트 등록 방식 (사용자 결정, 롤백됨)
- **자동 등록 / 자동 사라짐이 맞다**: 로그인한 클라이언트는 활성 프리셋에 자동으로 들어오고, 꺼지면 목록에서 사라진다 (배치·단축키 설정은 프리셋에 남아 있어 다시 로그인하면 복원).
- 한 번 만들었던 `+`(직접 추가 팝업) / 휴지통(삭제 모드) / 꺼진 캐릭터 표시 방식은 "오히려 불편하다"는 이유로 되돌렸다. 다시 제안하지 않는다.
- 유지: 프리셋 목록 줄에 마우스를 올려도 줄 높이가 변하지 않는다(아이콘은 Hidden 으로 자리 유지).

## 대시보드 (구현됨: 표 형태 — 시안 A)
- 구조: Core 의 `IDashboardContributor`(클라이언트 줄에 넣을 표시 / 요약 표시)를 모듈이 구현하고, `Argus.Ui.DashboardView` 가 0.5초마다 모아서 그린다 (내용이 바뀔 때만 다시 그림, 한 모듈이 오류를 내도 나머지는 정상). 대시보드는 다른 모듈을 직접 알지 못하며, 모듈을 빼면 그 모듈의 표시만 사라진다.
- 표시 하나(`DashboardChip`)는 들어갈 열(`DashboardColumns`: cycle / dps / logi / neut / status / watch)을 스스로 정한다. 아무 모듈도 채우지 않는 열은 표에서 빠지고, 모르는 열 이름은 '상태' 열로 간다. `Plain` 이면 알약 없이 글자만(숫자 열).
- 요약 띠: 실행 중 N + 모듈별(프리셋 이름, 프리뷰 켜짐/꺼짐, 사이클 N개, 감시 중 N개, 오늘 감지 N회, 전투 로그 N개 읽는 중).
- 클라이언트 표(한 줄에 하나): 이름(마우스를 올리면 PID, 앞에 있는 창이면 '활성' 표시와 파란 줄 배경) · 사이클·키 · ▼ 받는 DPS · ✚ LOGI · ⚡ 뉴트(숫자, 0 이면 흐리게, 뉴트는 캡이 빠지면 빨강 -, 늘어나면 파랑 +) · 상태(레드박싱 / HIC / SCRAM / DISRUPT / 프리뷰 숨김, 상태 열에 Bad 칩이 있으면 줄이 붉은 기운) · 화면 감시(감시 상태·마지막 감지·메모).
- 빠른 동작 버튼(프리뷰 표시·배치 편집·프리셋 메뉴·감시 전체 시작/중지)은 표로 바꾸면서 **없앴다** (사용자 결정). 계약에서도 `Actions()` 를 삭제했다.
- 다음 후보: 최근 감지 목록(썸네일), 모듈 상태 패널.

## 레드박싱 (구 '피격 급증')
- 이름을 '피격 급증'에서 **레드박싱**으로 바꿨다 (설정·프리셋·기능 테스트·대시보드 문구 모두). 판정 규칙과 설정 값은 그대로.
- 코드 안의 내부 이름(`SurgeAt`, `SurgeDetector`, `SurgeSeconds`, `HudSurge` 등)은 설정 파일 호환을 위해 그대로 둔다.

## 기능 테스트 (설정 > 프리뷰 맨 아래, 별도 하위 항목 모듈 `PreviewFeatureTestModule`)
- 실제 전투 없이 HUD 를 시험: 대상(전체/클라이언트 하나) 선택 후 **레드박싱 발생**(진짜 레드박싱처럼 색조·키 안내·레드박싱 전환 단축키까지 동작), **리본**(디스럽트/스크램블/HIC/모두, 표시 시간 입력), **수치**(받는 DPS·LOGI·뉴트 중 고른 항목에 초기 수치 → 피크 수치로 천천히 상승 → 피크 유지 → 하강, 상승/유지/하강 시간 입력. 피크를 음수로 두면 뉴트 `+` 표시 시험).
- **수치 시험에서 받는 DPS 가 급히 오르면 실제와 같은 규칙(`Argus.Core.Combat.SurgeDetector`, 기준은 전투 로그 설정)으로 레드박싱이 일어난다.** 리본은 여러 개를 함께 골라 시험.
- 시험 값은 실제 전투 값 위에 겹쳐 적용되고 끝나면 실제 값으로 복귀. `모든 테스트 중지` 버튼. 시험 중에는 전용 타이머(50ms)로 곡선을 매끄럽게 갱신.

## HUD: A+ 안 (프리뷰를 붙여 배치해도 구분되도록 보강한 A안)
- 하단 수치 바: 받는 DPS / 받는 LOGI / 받는 뉴트 (앞에서부터 주황 / 청록 / 보라). **내가 입히는 DPS 는 뺐다(불필요, 사용자 결정)**. 수치는 `1.2k` 식으로 줄여 표기.
- 오른쪽 위 대각 리본: 디스럽터=초록 `DISRUPT`, 스크램블=파랑 `SCRAM`, HIC 포인팅=빨강 `HIC`. 색만으로 구분하지 않고 글자를 항상 함께 표시.
- 타일 안쪽 검은 1px 경계선, 이름 라벨 뒤판, 활성 클라이언트 = **흰색 이중 테두리** (초록은 디스럽터와 겹쳐 사용하지 않음).
- 리본은 항상 레드박싱 색조보다 위에 그린다 (색조가 리본 색을 바꾸면 안 됨).
- 표시 요소(수치 4종, 태클, 레드박싱 경고)는 **클라이언트마다 켜고 끌 수 있어야 한다.**

## 레드박싱 (4단계, 구현됨 — 기본값은 모두 설정에서 변경 가능)
- **판정**(전투 로그 설정): 최근 3초의 받는 DPS 가 **최소 DPS(기본 300)** 이상이고 그 직전 30초 평균의 **배수(기본 3배)** 이상. 한 번 감지하면 받는 DPS 가 기준 아래로 내려갔다 올라와야 새 레드박싱으로 센다 (같은 전투를 계속 새 레드박싱으로 세지 않음).
- **유지 시간은 설정 하나**(기본 **10초**, 2~60초): 붉은 색조, 전환 키 안내, 레드박싱 전환 단축키가 모두 레드박싱 후 이 시간 동안만 살아 있다 (예전에는 색조 시간·단축키 시간이 따로였으나 통일).
- **붉은 색조 깜빡임**: 위 유지 시간 동안, 깜빡임 주기 기본 0.7초(설정 0.2~2.0초). 태클 리본은 색조 위에 그린다.
- **레드박싱 전환 단축키**: 프리셋 설정 칸의 '레드박싱 클라이언트로 전환'. **평소에는 단축키 목록에 없어서 그 키를 가로채지 않고**, 위 유지 시간 동안만 동작. 레드박싱이 여러 곳이면 **먼저 감지된 클라이언트부터**, 누를 때마다 다음 레드박싱 순서로(끝에서 처음으로 순환).
- 레드박싱이 난 프리뷰 가운데에 그 단축키를 **밝은 회색**으로 표시 (설정으로 끄기 가능).
- 클라이언트마다 `HUD` 메뉴의 '레드박싱 경고'로 끄면 그 클라이언트는 색조·안내·전환 대상에서 빠진다.
- 레드박싱 전환 키도 겹침 경고 대상이다 (평소 동작 여부와 상관없이).
- 전투 로그 갱신이 3초 넘게 끊기면 색조를 지운다.

## 전투 로그 (3단계, 구현·실측 완료)
- 위치: `Documents\EVE\logs\Gamelogs\날짜_시각_캐릭터ID.txt` (UTC 이름). 머리글 `청취자:`(한국어) / `Listener:`(영어)로 캐릭터·언어를 알아내고, 캐릭터 이름 → 캐릭터 ID → 가장 최근 파일로 클라이언트와 연결. 읽기 전용(FileShare.ReadWrite|Delete), 처음 붙을 때는 파일 끝부터, 새 세션 파일이 생기면 처음부터.
- **모듈**: `Argus.Modules.CombatLog` 가 250ms 마다 새 줄을 읽어 캐릭터별 수치를 계산하고 500ms 마다 `CombatStatsUpdated`(Core 이벤트)를 발행. 프리뷰는 이 이벤트만 구독 (모듈끼리 직접 참조 없음). 설정 페이지에서는 프리뷰 그룹 아래 '전투 로그' 하위 항목 (`SettingsParentId`).
- **수치**(기본 최근 **10초**, 설정에서 3~60초): 받는 DPS / 받는 LOGI(원격 장갑 수리·실드 충전 받음) / **받는 뉴트 = 이펙티브 뉴트량**(GJ/초) = 받은 뉴트 + 노스 피해 − (내가 노스로 빤 양 + 원격 캐패시터 전송 받은 양). 노스로 빠는 것만 있어 순 값이 음수(캡이 늘어남)면 `+N` 으로 표시. 구간 합 ÷ 구간 초.
- **실측한 문형(한국어, 이 PC 로그 74,443줄로 검증 — 독립 집계와 줄 수 일치)**
  - 입힌 피해 `N 의 피해를 <대상>에게 입힘 - 무기 - 명중`, 받은 피해 `… 에 의해 입음 - …`
  - 받은 수리 `N: 원격 장갑 수리받음 - …`, `N: 원격 실드 충전받음 - …` (`원격 장갑 수리 -`(받음 없음)는 내가 준 것 → 제외, `캐패시터 원격 전송받음`은 캡 전송 → LOGI 아님)
  - 받는 뉴트 `-N GJ: 에너지 뉴트럴라이즈 - …` (부호 −가 받는 쪽 확인) + 노스 피해 `-N GJ: 에너지 흡수 당함` = 빠지는 캡. `+N GJ: 에너지 흡수`는 내가 노스로 빤 것, `N: 캐패시터 원격 전송받음`은 원격 캡 전송 받은 것 = 둘 다 채워지는 캡(순 뉴트량에서 뺌). 내가 보낸 `캐패시터 원격 전송-`은 제외.
  - **태클은 로그로 읽지 않는다 (2026-10-01 정리)**: 스크램블·디스럽트 시도 줄은 걸린 순간 **한 줄만** 남고(1분 넘게 유지돼도 추가 줄 없음) 풀림 기록도 없어서 '유지 중인지'를 알 수 없었다. 그래서 파서의 태클 줄·HIC 함선 목록·`태클 표시 유지 시간` 설정을 모두 없앴고, 태클은 **화면의 상태이상 아이콘**(`StatusIconModule`, 아래 '상태이상 인식')에서만 읽는다. `CombatSnapshot` 에도 태클 칸이 없다.
- **버블(범위 교란)은 로그에 남지 않아 제외**. 영어 문형은 알려진 형식으로 구현만 했고 실제 영어 로그로는 검증하지 못했다.
- **HUD**(A+): 프리뷰 하단 수치 바(▼받는 DPS 주황 / ✚LOGI 청록 / ⚡뉴트 보라·빨강·파랑, `3,000` 표기, 0 은 흐리게), 오른쪽 위 대각 리본(HIC 빨강 / SCRAM 파랑 / DISRUPT 초록, 글자 병기, 겹치면 안쪽으로 나란히 — 상태이상 아이콘에서 읽은 값). HIC 는 아이콘 색(분홍)으로 구분한다. 클라이언트 줄의 `HUD` 버튼으로 요소별(수치 3종·태클·레드박싱) 켜고 끔 (프리셋마다 저장). 전투 로그를 못 읽으면 수치 바를 그리지 않고(태클 리본은 별개), 3초 이상 갱신이 없으면 수치를 지움.
- 미확인: 영어 클라이언트 로그, 실전 전투 중 HUD 체감(반응성·깜빡임).

## 단축키 (2단계, 확정 — 사용자가 그림판 시안으로 지정한 구조)
- 단축키는 **프리뷰의 하위 기능**이고 **레이아웃 프리셋 안에 저장**된다. 별도 모듈·사이드바 항목·탭·설정 그룹으로 분리하지 않는다. 프리셋을 바꾸면 그 프리셋의 단축키가 적용된다.
- 프리뷰 화면 오른쪽 '클라이언트' 카드의 각 줄: `≡`(끌어서 순서 변경: 잡은 줄이 마우스를 따라오고(그림자·앞으로) 다른 줄들은 자리를 비켜주며, 놓으면 제자리로 미끄러져 들어감) · **사이클 순서 배지** · 이름(≡ 오른쪽, 줄 세로 중앙. 사이클 포함 클라이언트만 1, 2, 3… / 빠져 있으면 `-`) · **클라이언트 단축키 입력**(폭 고정) · **사이클 버튼** · **표시 버튼**. 사이클/표시는 스위치가 아니라 일반 버튼이며 꺼짐=흐리게, 켜짐=밝게(강조색). 위치 초기화 버튼은 없다(제거).
- **사이클 = 프리셋의 클라이언트 목록 순서.** 드래그로 위아래 순서를 바꾸면 그 순서대로 다음/이전 전환. 사이클 스위치가 켜진(기본 켜짐) 실행 중 클라이언트만 순환. 사이클 밖 창에서 누르면 첫 번째(다음)/마지막(이전).
- 카드 아래 **'프리셋 설정' 칸**: 그 프리셋의 **사이클 다음 / 사이클 이전 단축키**(등등 — 추후 프리셋 관련 설정이 늘면 여기에 추가). 겹침 경고도 여기에 표시.
- 새 프리셋은 현재 프리셋의 배치·사이클·단축키를 복사해서 시작.
- 입력: 키보드 키, 마우스 가운데/옆 버튼 + Ctrl·Shift·Alt·Win 조합. 일반 글자·숫자 키는 보조키 없이는 지정 불가(채팅 방해).
- **보조키를 누른 채로도 동작** (설정, 기본 켜짐): 락온에 쓰는 Ctrl 을 누른 채 계속 전환할 수 있어야 한다. 지정한 것보다 보조키가 더 눌려 있어도 동작하며, 보조키를 더 요구하는 단축키가 우선.
- **겹침 경고**: 같은 단축키를 두 동작이 쓰면(먼저 지정한 쪽만 동작), 보조키 포함 관계로 겹치면, 맨 F1~F8(EVE 기본 모듈 키)이면 경고 표시 + 해당 줄 ⚠. 지정 자체는 막지 않는다.
- 전역 옵션(설정 > 프리뷰): 단축키 사용, EVE/Argus 가 앞일 때만 동작(기본 켜짐), 보조키 허용.
- 기본 단축키: 처음 한 번 '기본' 프리셋에 마우스 옆 버튼 앞으로=다음, 뒤로=이전.
- 구현: `Hotkeys/` (전용 스레드의 저수준 키보드·마우스 훅, 일치하면 입력을 삼키고 전환은 다른 스레드에서). 주의: 관리자 권한(elevated)으로 실행 중인 창이 앞에 있으면 Windows 가 훅에 그 입력을 주지 않는다 — EVE 를 관리자로 실행하면 Argus 도 관리자로 실행해야 한다.

## 단축키 원칙
- 창 **전환만** 한다. 여러 클라이언트에 입력을 동시에 보내는 기능은 만들지 않는다 (CCP가 금지하는 입력 브로드캐스팅).

## 상태이상 인식 (태클 리본의 유일한 출처)
- **모듈**: `Argus.Modules.Capture/StatusIcons`(`StatusIconModule`, 설정은 프리뷰 그룹 아래 '상태이상 인식'). 화면 감시 캡처와 같은 창 캡처(WGC) 코드를 쓰려고 같은 어셈블리에 있지만 모듈 등록은 따로이고, 프리뷰와는 Core 이벤트 `TackleIconsUpdated` 로만 이어진다.
- **읽는 곳**: 각 클라이언트 화면 아래 가운데, HUD 바로 위의 상태이상 아이콘 줄(기본: 화면 아래에서 150px 위부터 높이 180px, 가운데에서 좌우 400px). 초당 5회.
- **판정**: 붉은 원 테두리를 찾고(고리 채도 165 이상) → 안쪽 모양이 태클 아이콘(디스럽터·스크램블·HIC 포인팅은 같은 모양)과 65% 이상 닮으면 태클 후보 → 위쪽 광채 색이 가장 가까운 기준 아이콘으로 종류(청록=디스럽터, 파랑·보라=스크램블, 분홍=HIC 포인팅). 기준 그림은 사용자 캡처를 내장 리소스로 넣었다. 노스·ECM·웹·센서 댐프너·웜홀 이펙트는 실제 캡처로 태클이 아님을 확인.
- **켜짐·꺼짐**: 연속 2번 보이면 켜고, 연속 3번 안 보이면 끈다. 읽기가 1.5초 넘게 끊기면(창 최소화, 모듈 끔) 리본도 꺼진다. 전투 로그로 되돌아가는 대비책은 **없다**.
- 대시보드의 태클 칩(HIC / SCRAM / DISRUPT)도 이 모듈이 내놓는다.
- 미확인: 실제 클라이언트를 WGC 로 읽는 동작(저장된 그림으로만 시험), UI 배율이 다른 클라이언트, 타겟 페인터·뉴트·트래킹 디스럽터 아이콘(오인식이 보이면 그때 캡처를 받아 조정).

## CCTV 웹앱 통합 (브랜치 `feature/cctv-web-merge`, 1단계)
- 출발점: 태그 `backup-2026-10-01`(= master). 백업 zip `D:\Argus_backup_20261001.zip`, 당시 exe `D:\Argus_backup_exe\Argus_20261001.exe`.
- **결정(사용자)**: 1단계 = Argus 안에 탭으로 넣기. Node 는 Argus 에 같이 넣기(`publish.bat` 이 PC 의 node.exe 를 `distuntime
ode.exe` 로 복사, 없으면 PC 의 node 사용). C# 재작성과 이벤트 연동(2단계)은 아직 하지 않음.
- **모듈**: `Argus.Modules.Cctv`(`CctvModule`, 사이드바 'CCTV' 탭, 설정 > CCTV). 웹앱 코드는 고치지 않는다. 웹앱 폴더는 설정(기본 자동: `D:\eve cctv web v2`)이고 Argus 안으로 복사하지 않는다.
- **실행**: Node 프로세스 2개(`local-service/server.mjs` = 서비스 8765, `scripts/run-framework.mjs dev` = 웹 화면 5173)를 창 없이 띄운다. 둘 다 응답하면 '실행 중'. 자식은 Windows 작업 개체(Job Object, KILL_ON_JOB_CLOSE)에 묶어 Argus 가 종료·비정상 종료해도 같이 끝난다. 프로세스가 죽으면 종료 코드와 마지막 출력 줄을 보여주고 남은 것도 정리한다. 포트를 이미 다른 것이 쓰면 시작하지 않고 안내(실행 중인 것을 죽이지 않음). 시작 시간 초과 120초.
- **화면**: WebView2 로 `http://localhost:5173` 을 탭 안에 표시(서비스가 '실행 중'이 된 뒤 처음 한 번 만들어 메모리를 아낀다). WebView2 런타임이 없으면 '브라우저로 열기'로 대체.
- **폴더 연결**: 웹앱의 CCTV 폴더가 비어 있으면 Argus 화면 감시 저장 폴더(`capture` 설정의 OutputFolder)로 자동 연결. **이미 지정돼 있으면 건드리지 않고**, 다르면 경고 띠와 '맞추기' 버튼(웹앱은 폴더를 바꾸면 분석 결과를 초기화하므로 확인창을 거친다).
- 자동 시작은 기본 꺼짐(설정에서 켬). 대시보드 요약 띠에 'CCTV 실행 중 / 시작 중 / 오류 / 꺼짐'과 분석 대기 장수.
- 시험: 가짜 웹앱 폴더로 시작·상태 읽기·폴더 연결·포트 충돌·종료·재시작·프로세스 사망·작업 개체를 확인(실제 웹앱 데이터는 건드리지 않음). **실제 웹앱을 Argus 로 띄워 본 것은 아직 없다** — exe 를 만든 뒤 CCTV 탭에서 확인 필요.
- 다음(2단계 후보): 웹앱 `/api/events`·`/api/stream` 으로 감지 이벤트(함선 진입·도킹 등)를 받아 Argus 알림·프리뷰 HUD·대시보드에 반영.
